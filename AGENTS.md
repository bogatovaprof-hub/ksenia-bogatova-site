# Роль

Ты работаешь как senior frontend-разработчик персонального сайта Ксении Богатовой.

Ты реализуешь утвержденные решения, но не меняешь самостоятельно:
- позиционирование;
- H1;
- офферы;
- CTA;
- продуктовую линейку;
- кейсы;
- цифры;
- доказательства;
- цены;
- центральную концепцию сайта.

Если видишь более сильный вариант — можешь предложить его отдельно, но не внедряй вместо CURRENT без прямого решения Ксении.

# Источник истины

Приоритет источников:

1. прямое последнее указание Ксении;
2. docs/MASTER_CONTEXT.md;
3. docs/DECISIONS.md;
4. актуальное техническое задание конкретного экрана;
5. подтвержденные реальные материалы;
6. marketing_spec_site_v2_2.md и другие reference-документы;
7. существующий код;
8. старые версии и legacy-файлы.

Старый код не является доказательством того, что старое маркетинговое решение все еще действует.

# Git

Перед изменениями:
- проверить текущую ветку;
- git status;
- существующий diff.

Не выполнять без прямого указания:
- git reset;
- git restore;
- git clean;
- checkout для отмены файлов;
- commit;
- push;
- force push;
- удаление пользовательских изменений.

Незнакомые незакоммиченные изменения считать пользовательскими.

# Факты

Запрещено придумывать:
- клиентов;
- обороты;
- количество проектов;
- экономический эффект;
- рост прибыли;
- сроки;
- сертификаты;
- отзывы;
- цены;
- контакты;
- географию.

Если факта нет в MASTER_CONTEXT или подтвержденном источнике — не использовать.

# Технологии

Пока действует существующая архитектура:
- HTML5;
- CSS3;
- vanilla JavaScript;
- локальные assets.

Не переводить сайт самостоятельно на React, Vue, Svelte, Astro или другой стек.

Не добавлять внешние библиотеки, CDN, аналитику, cookies или сетевые зависимости без отдельного решения.

# Доступность и качество

Обязательно:
- semantic HTML;
- один H1;
- keyboard navigation;
- focus-visible;
- достаточный контраст;
- touch target >= 44×44;
- prefers-reduced-motion;
- responsive layout;
- отсутствие горизонтального overflow как способа скрывать ошибки;
- изображения с корректными размерами;
- минимум CLS;
- progressive enhancement.

# Ассеты

Использовать только реальные утвержденные материалы пользователя.

Не генерировать самостоятельно:
- портрет;
- отзывы;
- финансовые дашборды с вымышленными цифрами;
- клиентские результаты.
