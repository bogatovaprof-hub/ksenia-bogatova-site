Дата: 2026-09-03. Основной файл: `index.html`.

Актуальное оформление обновлено по последующему указанию Ксении: визуальный образец — `variants/system.html`. См. `docs/VISUAL_SYSTEM_REVIEW.md`. Ниже сохранён отчёт о первоначальной реализации; его размеры отступов, описание тёмного контакта и прежние снимки относятся к состоянию до переноса оформления.

## Что проверено и почему потребовались изменения

Приоритет — последнее задание из приложенного pasted-text.txt. Оно прямо разрешает изменения основного сайта и заменяет прежние решения о форме, мини-брифе, трёх концепциях и поэтапной остановке.

До реализации проверены AGENTS.md, текущая ветка, git status и существующий diff. Изучены основной HTML, CSS, JS, MASTER_CONTEXT, DECISIONS, раздел «Система для решений» в экспертном брифе, факты и границы услуг в reference-спецификации. Найдены реальный портрет в двух WebP-размерах, JPG fallback и исходное видео. Обезличенных иллюстраций кейсов и подходящего постера видео среди файлов проекта нет.

Ветка: `codex/client-first-prototype-v2`. До задачи уже были изменены index.html и assets/js/site.js и существовали незакоммиченные варианты и документы. Git reset, restore, checkout, clean, commit и push не выполнялись.

Причина переработки: прежний index.html и site.js содержали отменённый сценарий с диалогом, формой, подготовкой и копированием сообщения, UTM/sessionStorage. Старый site.css содержал несколько поколений стилей. Эти зависимости мешали требуемому прямому контактному сценарию.

Исправление ограничено основным сайтом и его общими ресурсами: сохранены vanilla HTML/CSS/JS, текущая двухколоночная композиция hero, кремовый фон, тёмно-синий цвет, золотое подчёркивание и реальные изображения. Новые тексты, состав и цены взяты из последнего задания.

## Реализовано

1. **Первый экран** — точный H1, согласованные основной текст и CTA, объяснение бесплатной встречи, статичные 19 / 8 / 4 года. Портрет без подписей поверх изображения. На мобильном: текст → CTA → портрет → факты.
2. **Вопросы собственника** — ровно три карточки. В каждой нативные details/summary, по умолчанию закрытые. С JavaScript открыта максимум одна. Отдельных CTA в карточках нет.
3. **Финансовая система** — тёмный раздел, четыре этапа с текстовой версией, направлением связи и возвратом результата в следующий цикл. Распределены роли Ксении, команды и собственника. Все этапы видны без JavaScript.
4. **Практика** — поясняющая врезка о налоговом и управленческом учёте и две кейс-панели. Два месяца и договор примерно за неделю отмечены как факты; 1,3% — прогноз; 25% — предварительная оценка. Добавлены нейтральные места для доказательных материалов.
5. **Форматы** — ведущая услуга от 150 000 ₽ с составом нижнего ориентира; подчинённые сопровождение от 90 000 ₽/месяц, модель от 45 000 ₽, аудит индивидуально. Один общий CTA. Месяц запуска не назван регулярным сопровождением CFO.
6. **Почему Ксения** — три компетенции, опыт, удалённая работа по договору, ответственность в details. Реальное видео только здесь: controls, playsinline, preload=metadata, без autoplay, ширина до 720 CSS px.
7. **Первый шаг** — тёмный раздел, четыре шага, границы диагностической карты, десять вопросов FAQ, контакты. Отдельно — подвал и ссылка на privacy.html.

Шапка закреплена; на desktop четыре пункта. На мобильном нативное меню с aria-controls, JavaScript синхронизирует aria-expanded; без JS используется собственная семантика details. Escape возвращает фокус на меню, выбор ссылки закрывает меню и переносит фокус к разделу. Все якоря учитывают высоту шапки. Переходы непосредственные, без удержания или перехвата прокрутки.

## Контакты и юридические placeholders

В `assets/js/config.js`:

- `maxUrl: ''` — место для MAX_URL.
- `email: ''` — место для CONTACT_EMAIL.
- `legalName: 'ИП [полное имя]'`.
- `inn: '[будет добавлен]'`.
- `ogrnip: '[будет добавлен]'`.
- `address: '[адрес]'`.

На privacy.html дополнительно видны [ФИО ИП], [ИНН], [ОГРНИП], [адрес], [e-mail]. Финального юридического текста нет.

Пока контакты пустые, CTA ведут к #contact; там обычные сообщения «Ссылка на MAX будет добавлена перед публикацией» и «Рабочий e-mail будет добавлен перед публикацией». Пустых внешних переходов нет.

После заполнения maxUrl герой может вести прямо в MAX; ссылка открывается с target=_blank и rel=noopener. E-mail получает mailto без темы, текста и параметров. Значения проходят проверку; реквизиты вставляются как текст. Header и остальные CTA сохраняют переход к контактному разделу.

- Подтверждённая ссылка MAX и проверка реального перехода.
- Рабочий e-mail и проверка почтового клиента.
- Полное имя ИП, ИНН, ОГРНИП, адрес.
- Утверждённый текст политики.
- Обезличенный фрагмент 1С/финансовой системы для торгового кейса.
- Обезличенный фрагмент финансовой модели для кейса аренды.
- Разрешения на публикацию материалов; текстовая расшифровка рекомендательного письма, если оно будет предоставлено.
- Точная публичная формулировка показателя 45%, если впоследствии потребуется его использовать. Сейчас 45%, 0,4% и 11% на сайте отсутствуют.
- Цена углублённого аудита, если будет принято решение показывать её числом. Сейчас согласованное «Индивидуально, после диагностической карты».
- Финальная сверка исходных документов, статуса и контекста всех чисел кейсов перед публикацией.
- Подходящий постер и при необходимости субтитры для видео. Постер не был предоставлен; браузер показывает кадр самого ролика.

Сайт не опубликован; noindex, nofollow сохранён на обеих страницах.

## Как запустить и повторить проверку

В PowerShell из папки проекта:

```powershell
Set-Location -LiteralPath 'D:\0 кодекс\мой сайт'
node scripts/preview-prototype.mjs
```

Открыть http://127.0.0.1:4175/. Сервер слушает только localhost, отдаёт публичные страницы и assets, не отдаёт документы проекта или .git. Для работы самого сайта сборка и npm не нужны; Node используется только для удобного локального просмотра и проверки.

Проверка исходников:

```powershell
node scripts/check-prototype.mjs
```

Дополнительные режимы проверочного сервера: `--no-js` и `--reduced-motion`; другой порт можно задать через SITE_PREVIEW_PORT. Эти режимы изменяют только HTTP-ответы отдельного процесса, не сохраняют изменения в файлы сайта.

Минимальный следующий шаг к публикации: заполнить подтверждённые значения config.js, утвердить политику, добавить реальные доказательства, проверить перечисленные ограничения и только после отдельного решения снять noindex и публиковать.
