# Три варианта сайта на основе первой концепции

Дата: 3 сентября 2026 года. Статус: DRAFT / НА СОГЛАСОВАНИИ.

## 1. Что сделано

По прямому запросу Ксении созданы три полноценные отдельные страницы. Одобренная логика прототипа сохранена: первый экран → три ситуации → практика → совместная работа → форматы → о Ксении → первый шаг и FAQ.

Главные акценты:

| Вариант | Первый экран | Назначение |
| --- | --- | --- |
| 1 · Система | Финансовая система, с которой понятно, что делать дальше | Самый близкий к первой концепции: причины, варианты действий и проверка результата |
| 2 · Деньги | Сколько бизнес зарабатывает. И сколько можно забирать себе. | Прибыль, свободные деньги, запасы и средства собственника |
| 3 · Развитие | Что приносит прибыль. Где искать возможности для роста. | Контроль работающего бизнеса и оценка новых решений |

Это не три разных продукта и не три набора цен. Между страницами изменены тексты hero, ситуаций, заголовков практики, совместной работы, вводной части форматов, блока о Ксении, первого контакта и первого вопроса FAQ. Фактическое содержание кейса, опыт, стоимость и границы услуг одинаковы.

Сверху находится переключатель страниц. Он рассчитан на переход к текущему разделу; для раскрытой ситуации сохраняет её якорь. Переключатель внизу открывает выбранный вариант с начала. Данные формы между вариантами не переносятся.

Сохранены HTML/CSS/vanilla JavaScript и реальные локальные материалы. Использованы существующие стили и логика формы; библиотеки, сетевые зависимости, вымышленные визуалы и показатели не добавлялись.

## 3. Источники и сохранённые ограничения

Текстовая основа — [первая концепция](<D:/0 кодекс/мой сайт/marketing_spec_site_v2_2.md:354>): «Что продолжать, что срочно начать, а от чего отказаться, чтобы бизнес больше зарабатывал и эффективнее использовал деньги».

- финансовый директор как основная профессиональная роль;
- подтверждённый опыт 19 / 8 / 4 года;
- существующий портрет;
- обезличенный торговый пример без числовых результатов и неразрешённых клиентских файлов;

## 4. Проверки

### PASS — проверки исходников и локальной отдачи

Выполнены:

- `node --check` для новых JavaScript-файлов.
- `node scripts/check-concepts.mjs`: все три страницы прошли проверки.
- Баланс явно записанных HTML-тегов, один H1, семь секций, уникальные ID.
- Существование локальных ссылок, изображений и подключений стилей/скриптов; 16 ссылок на локальные файлы проверено на каждой странице.
- Существование якорей, целей aria-labelledby / aria-describedby и связей label → поле.
- Три сценария, шесть FAQ, одна форма, два обязательных поля.
- Шесть ссылок сравнения на каждой странице, корректное aria-current.
- Одинаковое содержимое блока услуг и цен во всех вариантах.
- Наличие noindex, nofollow и прежних ограничений CSP.
- Четыре unit-проверки переключателя на имитации DOM: первый экран, раздел практики, раскрытая ситуация, возврат с нижнего переключателя к началу.
- HTTP 200 для трёх страниц и десяти используемых файлов ресурсов.
- HTTP 404 для запросов к MASTER_CONTEXT, DECISIONS через путь с переходом в родительский каталог и .git/config.
- HTTP 405 для POST; HTTP 200 для HEAD страницы.
- `git diff --check`: ошибок пробелов не найдено. Предупреждения Git о будущей нормализации LF → CRLF относятся к существующим незакоммиченным файлам; они не форматировались.

Проверка HTML в скрипте является проверкой структуры исходника, а не полной проверкой стандарта HTML или браузерным аудитом.

### WARN — что не проверено

В этой задаче скриншоты, клики и измерения viewport в браузере не выполнялись. Новые длинные заголовки и дополнительная панель сравнения требуют отдельной визуальной проверки. Результаты прежнего QA прототипа v2 не считаются проверкой этих трёх страниц.

В коде сохранены адаптивные правила и добавлены правила переключателя для узких экранов. Для будущего визуального QA предусмотрены: 320×568, 360×800, 390×844, 412×915, 768×1024, 820×1180, 1024×768, 1280×720, 1366×768, 1440×900, 1920×1080. Это план проверок, а не выполненные viewport-тесты.

Не проверены реальные мобильные устройства, Safari/Firefox, скринридер, реальное поведение клавиатуры и формы на новых страницах, переходы в MAX/e-mail, clipboard, полевые показатели производительности и реакция реальных клиентов.

Общая логика формы не изменена, но это не заменяет её проверку в новых страницах.

## 5. Риски, минимальные действия и проверка результата

- Риск: длинные формулировки могут менять высоту первого экрана. Минимальное действие после выбора текста — проверить переносы и отступы, не переписывая содержание без согласования.
- Риск: панели сравнения не относятся к финальному сайту. После выбора редакции перенести согласованный текст в основной сайт и убрать служебное сравнение только по отдельному указанию.
- Риск: сила доказательства ограничена имеющимися материалами. Использовать новые числовые кейсы только после проверки источников и разрешения, а не подставлять примерные результаты.
- Риск: три редакции могут по-разному попадать в потребности двух типов клиентов. При просмотре отдельно оценить владельца торговли и владельца прибыльного производства с арендным направлением.

Как сравнить: открыть вариант 1, прочитать первый экран и раскрыть знакомую ситуацию; перейти на 2 и 3 через верхнюю панель; затем сравнить разделы совместной работы и первого контакта. Нижняя панель возвращает к началу выбранной версии.
